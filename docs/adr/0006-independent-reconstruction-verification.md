# ADR 0006: Independent reconstruction verification

- Status: Accepted
- Date: 2026-09-24

## Decision

Retain exporter-based round-trip equality, but never use it as the only fidelity
oracle. Integration checks source and destination directly against explicit seed
expectations for types, ordered keys, comments, defaults, grants, view restrictions,
and validity. These expectations are not generated by OracleCatalog or model
serialization. Disposable destination DML verifies defaults, rounding, and view
restrictions and is rolled back. Source verification remains read-only.

Test comparison tokenizes quoted literals, quoted identifiers, alternative quotes,
and comments before ignoring inter-token whitespace or redundant outer expression
parentheses. It preserves literal contents exactly. This helper is test-only and
does not change the trusted SQL fragment boundary or rewrite generated SQL.

The default ALL catalog extraction runs with a passwordless proxy target granted
only CREATE SESSION and SELECT on fixture objects. A second restricted target
lacks dependency grants and must fail closed for FK and view closure. Assertions
verify effective privileges, absence of roles, and rejection of DBA catalog access.
SYSTEM authenticates proxy connections using the existing environment secret; its
administrative privileges do not become the target session's privileges.

Offline GitHub Actions checks run for pushes and pull requests. Oracle verification
is a separate manually dispatched job with disposable Compose databases and cleanup.
Repository administrators configure the offline job as required in branch protection.
Hosted CI execution and branch-protection configuration are external to local tests.

## Consequences

A defect repeated by both extractions can still pass model equality, but the fixed
catalog and behavior expectations detect defects in the selected semantics.
This is deliberately bounded evidence, not a proof of every Oracle feature.
Fixtures cover literal spaces/quotes/parentheses and character/numeric boundaries.
Existing strict catalog corruption and semantic closure coverage remains required;
view dependency cycles are rejected, while table self-FKs and cycles between explicit targets are supported.
No production schema format, API, supported-feature boundary, or pipeline invariant
changes. Old disposable source volumes need fresh seeding for the reader accounts
and boundary columns. See README for provisioning and resource requirements.
